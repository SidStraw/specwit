05 — GO DEEPER

理解承諾，也理解界線。

架構的價值，在於能被檢驗。
從核心名詞到完整規格，繼續往下探索。

Gate A 與 Gate B 有什麼不同？＋

Gate A 依固定規則檢查可觀察行為，例如請求次數、錯誤狀態與設定變動。Gate B 發現架構、抽象與需求解讀的語意風險，提供位置、理由與待處置事項。Gate B 沒有發現問題，不等於成果正確。

Behavior IR 為什麼還需要 Project Binding？＋

「送出失敗後保留輸入」描述的是行為；Project Binding 補上真實路由、按鈕 selector、API transport、fixture 與啟動方式。兩者搭配固定版本的 Verifier Pack，才有可執行的驗收計畫。Binding 缺漏必須揭露，不能任意猜測。

PASS 是不是代表可以直接合併？＋

PASS 只描述指定情境的驗證結論。接受資格還需要證據有效、必要人工項目已處置、沒有阻擋風險，且授權有效。Apply、push、merge 與 deploy 各自需要相應授權；整合版本改變時，也需要重新驗證。

為什麼「未知」不能算通過？＋

驗證環境壞了、檢查未執行，或證據對應舊版本，都不能支持現在的成果。INCONCLUSIVE、NOT_RUN 與 STALE 會阻擋自動接受，直到補足證據或依政策完成明示處置。人工項目不會被改寫為自動 PASS。

目前可以使用到什麼程度？＋

目前是 v0.2 架構討論稿與本網站的概念模擬，治理核心、Harness adapter 與隔離驗證尚未實作。建議先以單一前端專案、單一 Harness 與六類行為範本做 Prototype，量測接入成本、缺陷偵測與淨人工工時，再逐步擴充。
